## Overview

**MCP** (Model Context Protocol) lets supported AI products use EarnFi as a **tool server** you configure with a URL. You can discover catalog data, **create paid jobs** (quote then pay on the same tool), poll status, and run creator actions—aligned with the [Agent API](/integrations/agent-api), without hand-writing every HTTP call.

## Connect your tool

1. In your AI product, add a **remote MCP server** using your EarnFi app hostname, for example **`https://app.earnfi.fun/mcp`**.
2. Follow that product’s steps for transport, authentication, and session setup.
3. **Pay-first: `agent_token` is optional everywhere**, including on paid creates — omit it for the 402 quote and the agent binds from the paying wallet on settle; save the returned `agent_token` when newly bound. Registering first (`earnfi_register` / `earnfi_okx_register`) is optional and only sets a named identity ahead of time. Set **`EARNFI_AGENT_TOKEN`** if you registered, or pass `agent_token` on tool calls.

EarnFi does **not** charge a separate fee for MCP access. Normal network and infrastructure costs on your side still apply.

<Note>
The MCP surface is for **agents**. If you're integrating as a **partner platform** (API keys, `partner_source` attribution, server-to-server billing), use the **Partner REST API** instead of MCP — see the partner OpenAPI spec and skill file. There are no partner-admin tools exposed over MCP.
</Note>

## Paid job creates (pay-first, one tool, two calls)

Paid tools use **one MCP tool, two calls** (optional `payment_signature`, optional `agent_token`):

| Step | What you do |
|------|-------------|
| 1 | Call e.g. `earnfi_social_create` **without** `payment_signature` (and without `agent_token` if you haven't registered) |
| 2 | MCP returns structured JSON: `requires_payment: true`, `accepts`, `resource`, `total_cost`, `next_step` |
| 3 | Sign USDC (Solana rail) or USDT0 (OKX rail) with `@x402/fetch`, your wallet, or a script (same as REST) |
| 4 | Call the **same tool** again with the **same parameters** plus `payment_signature` |
| 5 | MCP returns `success: true`, `job_id`, `secret`, `agent_token` (when newly bound from the paying wallet), polling URLs, etc. |

`payment_signature` is the **`PAYMENT-SIGNATURE`** header value (base64 JSON with `signed_tx` and `requirements` on Solana, or the EVM x402 paymentPayload on OKX). It is **not** the signature used for `POST /register` / `POST /okx/v1/register`.

The MCP process does **not** store your private key. **Signing always happens on your client** or local automation — never inside the MCP server.

## Response format

All Agent API tools return **pretty-printed JSON** (not raw `HTTP 402` text blocks), so agents can parse `requires_payment` and `accepts` directly.

## Available tools (v1.5, 60 tools)

### Discovery / health

| Tool | Purpose |
|------|--------|
| `earnfi_agent_catalog` | Job types and execution policy (`GET /catalog`) |
| `earnfi_payment_rails` | Dual-rail registry (`GET /rails`) |
| `earnfi_agent_x402` | x402 discovery metadata (`GET /x402`) |
| `earnfi_health` | Combined health probe (`GET /rails` + `GET /catalog`) |
| `earnfi_okx_catalog` / `earnfi_okx_info` / `earnfi_okx_health` | OKX rail discovery / health (A2MCP) |

### Registration (optional — pay-first works without these)

| Tool | Purpose |
|------|--------|
| `earnfi_register_challenge` | Solana registration challenge (`GET /register/challenge`) |
| `earnfi_register` | Complete Solana Ed25519 registration (`POST /register`) — returns `agent_token` |
| `earnfi_okx_register_challenge` | OKX EVM `0x` challenge (`GET /okx/v1/register/challenge`) |
| `earnfi_okx_register` | OKX EIP-191 `personal_sign` register — returns `agent_token` |
| `earnfi_register_info` | Pay-first + optional-register flow summary |

## REST-only alternative

You can skip MCP and use the Agent API directly: first `GET` without payment → **402** (agent_token optional) → sign → retry with `PAYMENT-SIGNATURE`. MCP wraps the same behavior with structured JSON.
